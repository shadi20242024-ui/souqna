# سوقنا – حزمة إصدار قابلة للتنزيل للنشر بعد التحقق

**اسم المشغّل المعروض للجمهور:** شادي (Shadi) فقط.  
**مشروع Firebase المقصود:** `souqna-sweida`.  
**نوع الإصدار:** موقع ويب متجاوب وقابل للتثبيت (PWA).  
**حالة الإصدار:** **حزمة إصدار إنتاج مرشحة وليست إطلاقاً تجارياً معتمداً**. لم يُنشر Backend الإنتاج أو قواعد Firestore أو تُجرّب عمليات دفع حقيقية ضمن عملية بناء هذه الحزمة.

## محتويات ZIP
- `dist/`: ملفات الواجهة النهائية المجمعة للاستضافة (ترتبط بإعداد Firebase Web العلني لمشروع الإنتاج، وليست معاينة).
- `firebase.json`: إعداد نشر Firebase الرسمي للموقع والقواعد والدوال.
- `firestore.rules`: قواعد الأمان التي يجب مراجعتها واختبارها وتوثيق نسخة احتياطية من القواعد الحالية قبل التغيير.
- `functions/`: الدوال السحابية اللازمة للعمليات المالية والإعلانات والمتاجر والمراجعة؛ تشغيلها قد يستدعي تفعيل خطة فوترة Firebase، لذلك لا تُنشر تلقائياً.
- `docs/`: دليل نشر مفصل، واختبارات قبول Staging، ومسودة سياسة الاسترداد التي لا تزال تتطلب اعتماد المالك والمراجعة القانونية.
- `RELEASE_MANIFEST.json`: معرف الالتزام الذي بُنيت منه الحزمة وسبب عدم إعلان الجاهزية التجارية.

## طريقة التجربة الفورية بلا بيانات حقيقية
توجد نسخة معاينة تفاعلية مخصصة لهذا الغرض على Vercel، مفصولة عن بيانات Firebase. ليست هذه الحزمة؛ هذه الحزمة تربط واجهة الإنتاج بمشروع `souqna-sweida` الحقيقي. **لا ترفعها إلى استضافة عامة للتجربة قبل التأكد من الجاهزية**؛ قد تتصل بمشروعك الحقيقي فور فتحها.

## ما الذي يلزم قبل نشر الحزمة إلى Firebase؟
1. راجع `docs/PRODUCTION_RELEASE_RUNBOOK_AR.md` ووافق على الشروط والخصوصية وسياسة الإلغاء والاسترداد بعد مراجعتها الملائمة، وتحقق من قناة الدعم.
2. افحص في **souqna-staging** استقبال الحسابات وموافقتها وحفظ الملفات والصلاحيات والمتاجر وإدارة النجوم باستخدام بيانات تجريبية، واجتز حالات القبول التسع عشرة. نجاح اختبارات GitHub المحلية وحده غير كافٍ.
3. راجع تكاليف Cloud Functions وحدود الفوترة، ولا تفعل أي فوترة دون موافقة منك.
4. أنشئ نسخة احتياطية من بيانات الإنتاج وقواعد الأمان الحالية، واختبر استعادة البيانات في مشروع مستقل، وتحقق من هوية المدير وصلاحياته.
5. تحقق من ارتباط النطاقات في Firebase Authentication، وجهّز مراقبة الأداء وخطة التراجع عند حدوث خطأ، ثم اعتمد الالتزام المحدد في `RELEASE_MANIFEST.json`.

### تعليمات التشغيل على Windows بعد تحقق الشروط السابقة
تحتاج Git، Node.js وFirebase CLI وحساب Firebase المخول. لا ترسل بيانات اعتماد حساسة إلى أي شخص. افتح PowerShell داخل مجلد الحزمة بعد فك الضغط، ثم نفّذ هذه **الفحوص فقط أولاً**:

~~~powershell
node --version
npx firebase-tools --version
npx firebase-tools projects:list
~~~

تأكد أن `souqna-sweida` هو مشروعك المقصود وأنك تملك تصريح التعديل. تحتاج الدوال إلى تثبيت اعتماداتها أثناء النشر. لا تنفذ أوامر Firebase التالية إلا بعد اجتياز الشروط أعلاه، ومع فهم أن التحديث قد يمس المستخدمين الحاليين:

~~~powershell
npx firebase-tools deploy --only functions:souqnaFinance,functions:souqnaMarketplace,functions:souqnaModeration --project souqna-sweida --config firebase.json
npx firebase-tools deploy --only firestore:rules --project souqna-sweida --config firebase.json
npx firebase-tools deploy --only hosting --project souqna-sweida --config firebase.json
~~~

**مهم:** النشر ليس معاملة ذرية، ولا تفترض أن الدوال وقواعد Firestore متوافقة مع البيانات الحالية دون اختبارات. عند فشل أي مرحلة توقف ولا تتابع إلى Hosting، وراجع السجلات. لا تُعد تشغيل حركة مالية ربما نُفّذت أو تسترجع قواعد أقدم متساهلة بلا تدقيق.

## ما الذي لا تقدمه هذه الحزمة؟
- لا تتضمن نسخة APK أو تطبيق iOS متجر.
- لا توثّق أن Firebase الإنتاجي متصل ومجرب فعلياً أو أن لوحة المدير تعمل على الإنتاج.
- لا تفعّل مدفوعات آلية أو النشر الآلي لـ Facebook/Instagram.
- لا تثبت صلاحية المؤشرات المالية المحلية أو مزامنتها الحية من مصدر رسمي.
- لا تمنح موافقة قانونية أو تشغيلية تلقائية على بيع الباقات والاشتراكات.

**الاسم العام في التطبيق: شادي فقط، ولا يُعرض اسمك الكامل ضمن ملفات الواجهة المجمعة.**
