# سوقنا — اختبارات قبول نسخة Staging قبل الإطلاق العام

**المشروع الذي يُختبر:** `souqna-staging` فقط.  
**الحالة الافتراضية:** جميع الحالات `not_tested`، ولا تسمح بوابة الإنتاج بالانتقال حتى نجاح كل حالة موثقة من مالك المشروع.  
**المشغّل المعلن:** شادي (Shadi)، بريد الدعم `shadi20242024@gmail.com`.

## تعليمات مسؤول الاختبار

1. بعد نشر نسخة Staging المتوافقة من قواعد Firestore والدوال وHosting بصلاحيات المالك، وبعد نجاح `npm run check:staging:readiness`، افتح PowerShell من جذر المستودع.
2. شغّل الأمر:

   ~~~powershell
   npm run uat:staging:init
   ~~~

   يُنشئ `artifacts/staging-uat.json` مرة واحدة. الملف محلي ومُستثنى من GitHub؛ لن يستبدل أي تقرير موجود.

3. استخدم حسابات اختبار وبيانات وهمية فقط لإجراء الحالات المذكورة أدناه على الموقع التجريبي. بعد كل حالة، غيّر `status` من `not_tested` إلى `pass` فقط عند النجاح الفعلي، وحدّث `testedAt` بتاريخ الاختبار الحقيقي بصيغة UTC ISO 8601، وسجّل `note` موجزاً لا يتضمن بيانات شخصية.
4. افحص الملف:

   ~~~powershell
   npm run uat:staging:check
   ~~~

   يرفض البرنامج حالات غير ناجحة أو بدون دليل موجز، أو اختبارات مضى عليها أكثر من 30 يوماً، أو بتاريخ مستقبلي، أو ملفات تخص مشروعاً آخر. **هذه شهادة قبول صادرة عن المشغّل، وليست تحققاً تقنياً مستقلاً للبيئة الحقيقية.**
5. بعد اجتياز الاختبارات والتأكد من باقي بنود الإطلاق، تُستخدم نتيجة القبول ضمن `npm run preflight:launch` في فرع `main`. لا يوجد أي أمر نشر ضمن هذا الاختبار.

## مثال تعديله في الملف المحلي

~~~json
{
  "id": "public_ads",
  "status": "pass",
  "testedAt": "2026-11-19T11:00:00.000Z",
  "note": "Tested approved and hidden pending demo ads"
}
~~~

لا تُضف أسماء زبائن أو أرقام هواتف أو تفاصيل بطاقات أو كلمات مرور أو رموز JWT أو مفاتيح Firebase Admin. عند فشل أي حالة، احتفظ بها بحالة `not_tested` أو `fail`؛ لا تستخدم `pass` لتجاوز شرط حقيقي.
