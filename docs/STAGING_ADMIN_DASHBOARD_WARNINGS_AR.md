# إصلاح تنبيهات لوحة المدير في سوقنا – بيئة Staging فقط

## ما الذي ظهر في شاشة صاحب المشروع؟
- تسجيل الدخول إلى لوحة تحكم سوقنا نجح على `127.0.0.1:5000` وظهر اسم العرض «شادي» فقط.
- تحذير `سجل مراجعة المحتوى (permission-denied)` عند محاولة قراءة مجموعة `moderationAudit` من المتصفح.
- اختبار الأقسام أعطى `8 / 10`: الأقسام الموجودة مفعّلة، بينما `fashion` و`lost_found` غير موجودين.

## أولاً: استكمال القسمين من لوحة المدير دون Cloud CLI
افتح لوحة تحكم المدير، وانزل أسفل قسم «جاهزية الأقسام المصورة» إلى «إدارة الأقسام من لوحة التحكم». أضف كل قسم على حدة:

| الحقل | القسم الأول | القسم الثاني |
| --- | --- | --- |
| رمز القسم بالإنجليزية | `fashion` | `lost_found` |
| اسم القسم بالعربية | أزياء | مفقودات |
| الاسم بالإنجليزية | Fashion | Lost & Found |
| صورة القسم | fashion | lost_found |
| ترتيب الظهور | 9 | 10 |

اضغط «إضافة القسم» مرة واحدة لكل قسم. ثم «تحديث البيانات» للتحقق من ظهور `10 / 10`. إذا ظهر `permission-denied` أو خطأ حفظ، **توقف ولا تغيّر قواعد الأمان**؛ تحقق من صلاحية المدير والقواعد المنشورة.

## ثانياً: تشخيص مشكلة moderationAudit بلا أي كتابة أو نشر
من PowerShell في مجلد `souqna-test`، استخدم:

```powershell
git pull --ff-only origin feature/legal-help-2026-11-19
npm.cmd run check:staging:moderation
```

يفحص الأمر **القواعد المنشورة فعلياً** من Firebase Rules API، ويقرأ فقط حالة حساب المشغل وملف `users/UID` في `souqna-staging`. لا يغيّر كلمة المرور، ولا الصلاحيات، ولا البيانات.

- `DEPLOYED_RULES_OUTDATED`: القواعد المنشورة لا تحتوي الإذن المحمي اللازم لقراءة السجل. يحتاج الأمر مراجعة فرق القواعد والنسخ الاحتياطي من القواعد الحالية ثم نشر القواعد الصحيحة إلى `souqna-staging` بموافقة المالك. **لا تنشر إلى `souqna-sweida`**.
- `ADMIN_ROLE_NOT_ACTIVE`: ملف المستخدم في Firestore لا يحتوي `role: admin` رغم ظهور واجهة الإدارة؛ أصلح الهوية والصلاحية الموثقة فقط.
- `FIRESTORE_ADMIN_PROFILE_MISSING`: الملف `users/UID` غير موجود. لا تنشئه من واجهة العميل بصلاحية مرتفعة.
- `ELIGIBLE_BY_RULES_NOT_BROWSER_VERIFIED`: قاعدة الحماية المنشورة وملف المدير يبدوان متوافقين، لكن **هذا لا يثبت نجاح طلب المتصفح**. جرّب تسجيل الخروج والدخول مجدداً، ثم تحديث الصفحة أو فحص جلسة Firebase Auth مع رسالة الخطأ.
- `PROFILE_EMAIL_MISMATCH`: سجل Firestore الشخصي قد ما زال يحمل البريد القديم `gmail.om` الذي صُحّح داخل Authentication. لا تغيّر البريد أو الدور عبر قواعد أمن مفتوحة؛ يلزم مراجعة محفوظة ومقيدة لملف المستخدم.

## قواعد أمان حاسمة
- لا تغيّر `allow read: if isAdmin()` إلى `true` لمجموعة `moderationAudit`؛ السجلات قد تتضمن بيانات تشغيل حساسة.
- لا تمنح مستخدمين آخرين صلاحيات المدير لحل خطأ عرض.
- لا تنشر قواعد أو دوال Firebase الإنتاجية بسبب تنبيه في Staging.
- لا تستخدم بيانات زبائن حقيقية خلال الاختبار.

**ملاحظة:** الكود المحلي في `firestore.rules` يسمح بقراءة `moderationAudit` للمدير فقط؛ لذا لا بد من المقارنة مع القواعد **المنشورة** قبل تقرير السبب النهائي.
