# SOUQNA — ملف تجهيز الإطلاق النهائي (19 نوفمبر 2026)

**حالة القرار:** `NO-GO / غير مصرح بالنشر العام` حتى اكتمال الفحوص الحقيقية التالية. هذه الوثيقة لا تدعي نشر موقع أو تطبيق Android.

## المنتج الذي يمكن تجهيزه الآن

- تطبيق ويب عربي للسويداء، Desktop/Mobile، قابل للتثبيت كـ PWA، به صفحات الإعلانات والبحث والمتاجر المتعددة ومفضلة المستخدم والوظائف والدليل المحلي والإدارة والمساعدة والشروط.
- عرض حتى 4 صور مضغوطة ورابط YouTube/Vimeo آمن للإعلان، مع حدود تخزين في Firestore؛ التخزين الحالي داخل المستندات ليس حلاً للتوسع.
- نظام نجوم وباقات وإعلانات مدفوعة، ومطابقة إيصالات يدوية تحت إشراف الإدارة، وCloud Functions آمنة للموافقة وإدارة المتاجر والإعلانات. لا توجد بوابة دفع متصلة.
- نشر الإعلانات المدفوعة تلقائياً على Facebook/Instagram، وأسعار الدولار المحلية الرسمية والموازية والذهب والفضة عبر مصدر موثّق: **ليست خدمات فعّالة بعد**. لا يَعِد إعلان تجاري بها قبل تنفيذ وتحقق الربط.
- إصدار ويب/PWA فقط. حزمة Android APK/AAB وتوزيع متجر التطبيقات يحتاجان بناءً وتوقيعاً وفحصاً منفصلاً بعد تأكيد عنوان HTTPS النهائي.

## ما أُنجز برمجياً في المرشح الحالي

1. فصل إنشاء حزم `preview` و`staging` و`production`: حزمة الإنتاج تتطلب تصريح بناء نصياً مطابقاً لإصدار الشروط؛ تبقى عملية البناء محلية ولا تكتب إلى Firebase.
2. تقوية قواعد Firestore: اسم الحساب وبريده مطابقان لهوية Firebase Auth عند الإنشاء، حصر الأدوار وتعديلات الأسماء، حدود حقول المتجر وصوره، منع تزوير التقييمات وتغيير تاريخها أو تقييم متاجر غير منشورة، التحقق من خدمات الطلبات وتقييد تحديثاتها، وحماية حقول الإشعارات.
3. توافق واجهة تعديل التقييم مع تاريخ إنشائه الأصلي. قيود طول اسم الحساب ووصف الخدمة والتقييم.
4. تدوير ذاكرة PWA إلى `souqna-v15-release` لتحديث العملاء المتصلين، وإضافة ترويسات Hosting أساسية: `X-Content-Type-Options` و`Referrer-Policy` و`X-Frame-Options`.
5. `scripts/preflight-production.mjs` يفحص هوية المشروع الحقيقي، إصدار الشروط، الملفات العامة، وعدم وجود تسرب لملفات القواعد والدوال، وعدم وجود شريط بيئة تجريبية أو وسم `noindex`.
6. `scripts/production-launch-gate.mjs` قرار Go/No-Go للقراءة فقط، ولا يعد بنشر تلقائي. يسجل تقريراً محلياً في `artifacts/production-launch-readiness.json` دون أسرار أو كلمات مرور.
7. اختبارات محاكيات Firestore/Auth/Functions، قواعد المالية والأدوار، وبناء الحزم، وفحص سطح المكتب والهاتف في GitHub Actions. **يجب التحقق من نجاح أحدث تشغيل مرتبط بالالتزام النهائي، لا تشغيل أقدم.**

## خطوات الاستعداد للاختبار الحقيقي (Staging أولاً)

1. تحقق من حساب Firebase المشروع `souqna-staging`، هوية تطبيق Web، Auth Email/Password، Firestore وHosting وCloud Functions (`souqnaFinance` و`souqnaMarketplace` و`souqnaModeration`).
2. لا تنشر Cloud Functions بدون موافقة على خطة Blaze والتكلفة وحدود التشغيل. إذا كانت الدوال غير منشورة، لا يعد نشر موقع Staging وحده اختباراً وظيفياً كاملاً.
3. افحص المدير الحقيقي `SOUQNA_ADMIN_EMAIL` ودوره في Auth وFirestore من دون مشاركة كلمة مروره أو تغيير الصلاحيات على نحو عام.
4. راجع النصوص القانونية التي ما زالت **مسودة**: الاسم القانوني للجهة المشغلة وعنوان/قناة الشكاوى وخصوصية البيانات، إلغاء/استرداد المدفوعات، حذف الحساب والاحتفاظ بالسجلات والقُصّر.
5. ضع بيانات تجربة وهمية فقط. انشر قواعد Staging ثم Hosting في نافذة صيانة قصيرة، باستخدام مسار Windows المخصص بعد تصريح مالك الحساب؛ اختبر تسجيل حساب فعلي، تمييزه، إنشاء/مراجعة إعلان ومتجر، دفعات النجوم، الإشعارات والمفضلة.
6. شغّل `npm run check:staging:readiness` من جهاز Google Cloud مخوّل، وتحقق من نجاح جميع البوابات الست: Hosting، الدوال، القواعد القانونية، صلاحيات المدير، الأقسام، ملفات دليل الاستخدام.
7. جرّب النسخ الاحتياطي **والاستعادة في مشروع منفصل**، وتأكد من تطابق سجل النجوم وأي إيصالات يدوية (لم يُنفذ هذا التدريب سحابياً).
8. راقب حدود مستندات Firestore، الصور وحركة المرور، وأسعار خدمات Firebase، واحمِ عمليات التسجيل والنشر من الإساءة باستخدام App Check أو الضوابط الملائمة بعد اختبارها.

## بناء حزمة Production محلياً (لا ينشر)

بعد دمج ومراجعة التعديلات في `main`، من PowerShell على جهاز Windows 11:

~~~powershell
git switch main
git pull --ff-only origin main
npm install --ignore-scripts --no-audit --no-fund
npm install --prefix functions --ignore-scripts --no-audit --no-fund
npm test
$env:SOUQNA_PRODUCTION_BUILD_APPROVED = "souqna-sweida:2026-11-19"
npm run build:production
npm run preflight:production
~~~

- نجاح `build:production` معناه إنشاء الملفات في `dist/` **فقط**، لا تشغيل الموقع الحقيقي.
- يحظر إدراج بيانات Firebase Admin وService Account ومعلومات الدفع داخل الحزمة أو GitHub.
- لا تنشر `dist` قبل فحص البوابات الحقيقية وتحديد نافذة تغيير واعتماد منفصل.

## قرار Go/No-Go قبل أي نشر على الإنتاج

الأمر `npm run preflight:launch` يفحص أن الفرع `main` نظيف، والحزمة مكتملة، وجميع اختبارات Staging الحية ناجحة، ووجود التصريحات اليدوية الصريحة للمالك بشأن: الوثائق القانونية، الفوترة، تدريب استعادة النسخ الاحتياطية، النطاق/HTTPS ودومينات Authentication، الدفع اليدوي، الحماية، ومعرّف الإنتاج الصحيح.

فشل شرط واحد = **BLOCKED**، ولا توجد عملية `firebase deploy` ضمن البوابة. القيم اليدوية هي إقرارات من المالك وليست أدلة مستقلة؛ يجب الاحتفاظ بالمستندات وإثبات الاختبارات بجانبها.

قبل السماح بالإطلاق يجب توثيق:
- اسم الجهة المشغلة الرسمي ووسيلة تواصل الدعم والبلاغات، والنطاق المملوك، وتوافق سياسة الخصوصية مع القانون.
- صلاحيات Firebase الحقيقية، خطة الفوترة وحدود Cloud Functions، التحقق من App Check بحسب التدفقات المختبرة، وحماية الحساب الإداري.
- اختبارات تدفقات الدفع اليدوي، الإعلانات، المتاجر، الإشراف، الإشعارات، الصور والروابط، الطقس والأسعار (بتمييز المصدر الفعلي).
- اختبار الاستعادة ودليل التراجع، والمراقبة والتنبيهات، وعدم انقطاع تسجيل المستخدم عند انتقال قواعد Firestore وإصدار الواجهة.
- موافقة كتابية مستقلة على نشر `souqna-sweida`، مع مسؤول يتابع السجلات بعد النشر.

## ما يمنع وصف المشروع بأنه منشور أو جاهز 100%

- لم يُتحقق من قواعد وخدمات الموقع الإنتاجي المنشورة فعلياً، ولم يثبت نجاح اختبار قبول Staging الحي هنا.
- PR #3 وPR #4 مسودتان غير مدمجتين في `main`.
- تفاصيل الجهة القانونية والإلغاء/الاسترداد وبيانات الاتصال غير معتمدة بعد.
- خدمات النشر الاجتماعي والتغذية المحلية المتقدمة لم تكتمل، والدفع ليس آلياً، وملفات الصور تحتاج ترقية تخزينية قبل التوسع الكبير.
- لا توجد نسخة Android موقعة أو عنوان إنتاجي مفحوص من هذه الجلسة.

**القاعدة:** لا تفعيل فوترة، ولا تغيير Auth/Firestore/Functions/Hosting الإنتاج، ولا نشر عمومي، إلا بعد اجتياز Staging وموافقة المالك الصريحة ونسخ بيانات التشغيل واستعادتها تجريبياً.
