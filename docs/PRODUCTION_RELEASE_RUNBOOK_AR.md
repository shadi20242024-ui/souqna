# سوقنا – دليل الإصدار العام النهائي (إطلاق PWA)

**الحالة: مرشح جاهز لمسار الاعتماد، لكنه لم يُنشر للإنتاج من هذه المحادثة.**  
**المشروع التجريبي:** `souqna-staging`. **مشروع الإنتاج:** `souqna-sweida`.  
**اسم المشغّل المعروض للجمهور:** شادي (Shadi) فقط، بصفته الشخصية لا باسم شركة مسجلة. **بريد الدعم:** `shadi20242024@gmail.com`. تُحتفظ ببيانات الهوية القانونية بشكل خاص.  
**نطاق الإصدار الأول:** تطبيق ويب متجاوب وقابل للتثبيت (PWA)؛ وليس APK/AAB أو تطبيق App Store.

## 1. نطاق الخدمات الحقيقي

يشمل مرشح الإصدار الإعلانات وطلب نشرها ومراجعتها والمتاجر المتعددة للحساب الواحد، وباقات النجوم والتمييز والتحقق اليدوي من إيصالات الدفع، والوظائف والدليل المحلي والمشرفين والصلاحيات ومركز المساعدة والشروط والخصوصية، وبعض بيانات الطقس والأسعار المتاحة. **لا يعتبر النشر التلقائي على Facebook/Instagram أو تحديث أسعار الدولار الرسمية والموازية والذهب والفضة المحلية ميزة نشطة** إلى أن يكتمل ربطها والتحقق منها. لا توجد بوابة دفع فوري متصلة.

## 2. قرار الإطلاق: الموانع لا تملك اختصاراً

- [ ] مطابقة هوية المشغّل بوثائقه الرسمية في مسار خاص غير علني، وتحديد بلد الاختصاص وعنوان مراسلة مناسب للنشر، والتحقق من أي تصاريح أو تسجيل فردي مطلوب قبل التشغيل التجاري بعد مراجعة قانونية مناسبة.
- [ ] اعتماد نصوص الشروط وسياسة الخصوصية ومسودة سياسة الإلغاء والاسترداد `REFUND_POLICY_DRAFT_AR.md` وإجراءات حذف البيانات.
- [ ] اختبار إرسال واستلام والرد على الرسائل في بريد الدعم وتعيين مسؤول متابعته.
- [ ] اعتماد الفوترة ومتطلبات Cloud Functions والخطة الفعلية للتكلفة والتنبيهات والحصص؛ لا تفعّل Blaze تلقائياً.
- [ ] التحقق من صلاحيات Firebase للمدير وأدوار المشرفين دون أي مشاركة لكلمات مرور أو مفاتيح خدمة خاصة.
- [ ] نسخ بيانات Firestore والسجلات المالية احتياطياً **واستعادتها فعلياً في مشروع منفصل** قبل تعديل الإنتاج.
- [ ] إكمال اختبار Staging المنشور على Firebase الحقيقي واجتياز `check:staging:readiness` واختبارات التشغيل الـ19 في `STAGING_UAT_AR.md`.
- [ ] اختبار المدفوعات اليدوية والعمليات المتكررة والطلبات المتزامنة، وفحص سلوك العملاء الذين لديهم نسخة PWA قديمة.
- [ ] مراجعة طلب دمج #3 و#4 ودمجهما بالتسلسل بعد التدقيق، وتشغيل CI على الالتزام الأخير بفرع `main`.
- [ ] تحديد نافذة صيانة، ومسؤول مراقبة، وتوثيق موافقة منفصلة على مشروع `souqna-sweida` وعلى الالتزام الدقيق (SHA) المقرر نشره.

**عدم تحقق شرط واحد = NO-GO.** نجاح الاختبارات المحلية وحده لا يثبت اتصال Firebase أو جاهزية نشر المبيعات.

## 3. تجهيز جهاز الإصدار (Windows 11)

يحتاج المالك/المشغّل المخوّل إلى Node.js 22+ وJava 21+ وFirebase CLI (من npm) وGit وGoogle Cloud Application Default Credentials له صلاحيات قراءة Firebase وCloud Functions وFireStore Rules. استخدم الحساب الرسمي الخاص بالإنتاج. لا ترسل أي رمز وصول أو مفتاح Service Account إلى دردشة أو مستودع.

بعد اعتماد PR #3 ثم PR #4 وتشغيل الاختبارات على `main`:

~~~powershell
git switch main
git pull --ff-only origin main
$sha = (git rev-parse HEAD).Trim()
~~~

اضبط توقيعات المالك المطلوبة **فقط عندما تكون شروطها قد تحققت حقاً** على جهازك. الأسماء في `scripts/production-launch-gate.mjs`؛ من بينها `SOUQNA_SIGNOFF_LEGAL` و`SOUQNA_SIGNOFF_SUPPORT` و`SOUQNA_SIGNOFF_BILLING` و`SOUQNA_SIGNOFF_BACKUP` و`SOUQNA_SIGNOFF_DOMAIN` و`SOUQNA_SIGNOFF_PAYMENTS` و`SOUQNA_SIGNOFF_SECURITY` و`SOUQNA_SIGNOFF_PRODUCTION`. لا تضبطها بشكل افتراضي للتجاوز؛ هذه إقرارات تحت مسؤولية صاحب المشروع.

## 4. فحص الإصدار دون أي كتابة إلى السحابة

~~~powershell
.\scripts\release-production.ps1 -ConfirmProject souqna-sweida -ApprovedCommit $sha
~~~

بدون `-Publish` ينفذ السكربت اختبارات الكود، وبناء الإنتاج، والتحقق من الملفات، وبوابات Staging الحية والاختبارات التسع عشرة والتوقيعات، ثم يحفظ نسخة محلية للقراءة فقط من **قواعد الإنتاج المنشورة حالياً** في `artifacts/production-rules-backups/`. هذه نسخة قواعد أمان فقط وليست نسخة بيانات Firestore؛ يجب أخذ نسخة بيانات منفصلة وتجربة استعادتها. إذا تعذر الاتصال أو غابت الصلاحيات، يتوقف ولا ينشر.

- `npm run check:production:services` يفحص حالة الدوال الثلاث في بيئة الإنتاج بالقراءة فقط.
- `npm run check:production:legal` يفحص قواعد المستخدم والموافقة القانونية المنشورة بالقراءة فقط.
- `npm run check:production:hosting` يفحص واجهة الإنتاج ودليل الاستخدام وPWA والبريد المعلن على نطاقَي Firebase الافتراضيين. تشغيلها **قبل النشر** قد يفشل إن كان الموقع جديداً؛ ذلك لا يعني عيباً في الكود.

## 5. التشغيل الحقيقي – فقط بعد موافقة منفصلة

بعد اكتمال الخطوات السابقة ونجاح الفحص دون كتابة، يراجع المالك SHA المحدد وبصمات الحزمة ونسخ البيانات وخطة صيانة العملاء. لا تُشغّل هذه الخطوة لمجرد أن هذا المستند موجود.

~~~powershell
$env:SOUQNA_APPROVE_LIVE_WRITE = "souqna-sweida:$sha"
.\scripts\release-production.ps1 -ConfirmProject souqna-sweida -ApprovedCommit $sha -Publish
~~~

يتحقق السكربت مرة أخرى من جميع الشروط قبل أي كتابة، ثم يرتب النشر إلى **الإنتاج فقط**: الدوال الثلاث المحددة، ثم قواعد Firestore، ثم Hosting، ويوقف العملية عند فشل أي خطوة. لا يُفعّل الفوترة تلقائياً؛ الخدمات التي تتطلب خطة مدفوعة ستفشل إذا لم يعتمدها المالك بنفسه. لا تُعد عمليات النشر ذرّية؛ قد تحدث فترة انتقال قصيرة تتعطل خلالها بعض العمليات في واجهة قديمة. يلزم نافذة صيانة ولا يجوز البدء دون خطة لتوافق البيانات والأمان.

## 6. مراجعة ما بعد النشر

- جرّب دخول المدير من حسابه الحقيقي وتحقق من ظهور لوحة الصلاحيات الصحيحة.
- أنشئ حساب مستخدم تجريبي وفق قواعد الموافقة الجديدة، ثم جرّب الإعلان والمتجر وموافقة مشرف مختص.
- راجع عملية نجوم تجريبية **دون تحويل مال حقيقي**، وراجع منع ازدواجية العملية وسلامة الدفتر.
- تحقّق من عرض الصور والفيديو والمفضلة والبحث والدليل والأسعار مع توضيح المصدر والتاريخ.
- افتح الموقع من هاتف وكمبيوتر وثبّت PWA ثم افحص نسخته بعد تحديث Service Worker.
- اختبر روابط شروط الاستخدام والخصوصية وبريد الدعم، وسجّل حالة استقبال الرسائل.
- راقب logs والأخطاء والتكاليف والدوال، ولا تُعد تشغيل عمليات مالية ربما نُفذت.
- سجّل نتيجة كل مرحلة في محضر الإصدار وحالة GO/NO-GO بعد المراقبة.

**إذا فشل التحقق بعد أول كتابة:** أوقف معالجة الدفعات اليدوية إلى حين مراجعة الوضع. قد تكون بعض أجزاء الإنتاج نُشرت بالفعل، ولا يجوز إعادة القواعد القديمة تلقائياً إن كانت متساهلة أو غير متوافقة مع الواجهة الجديدة، ولا إعادة تنفيذ أمر مالي دون تدقيق سجله. وثّق الاستعادة والتغييرات قبل إعادة فتح الخدمة.

## 7. ملفات مرجعية

- `docs/FINAL_LAUNCH_PLAN_AR.md` — العوائق والاختبارات الفنية وتوقيعات المشغّل.
