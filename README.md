# سوقنا | SOUQNA – السويداء

منصة إعلانات ومتاجر وخدمات محلية، عربية ومتجاوبة مع الكمبيوتر والهاتف، مع إمكانية تثبيتها كتطبيق ويب تقدمي (PWA).

**الحالة: مرشح إطلاق قيد المراجعة، وليس موقعاً منشوراً نهائياً.** احتفظت التعديلات بقواعد الفصل بين `souqna-staging` و`souqna-sweida`، ولا يوجد نشر تلقائي للبيئة الإنتاجية.

## الوظائف البرمجية

- إعلانات السيارات والعقارات والوظائف والأجهزة والأثاث وغيرها؛ صور متعددة وروابط فيديو خارجية.
- حسابات المستخدمين ومتاجر متعددة لكل حساب، مع باقة مستقلة للمتجر.
- نجوم وطلبات تمييز وبنرات وخدمات مع إشراف يدوي على إثبات الدفع، وسجل معاملات محمي عبر Cloud Functions.
- لوحة مدير ومشرفين بحدود اختصاص، موافقة على الإعلانات والمتاجر، إحصائيات الإدارة، ودليل خدمات محلي.
- طقس السويداء والحاسبة ومؤشرات الأسعار والنشرات المحلية بحسب المصدر المتاح.
- دليل الاستخدام وشروط الاستخدام وسياسة الخصوصية داخل التطبيق؛ تسجيل الموافقة بالنسخة وتوقيت الخادم.

**مهم:** النشر التلقائي على صفحات Facebook/Instagram والأسعار المحلية التفصيلية (الدولار الرسمي والموازي والفضة والذهب المحلي) مميزات **قيد العمل** وليست مفَعّلة أو مضمونة. لا توجد بوابة دفع إلكترونية أو نسخة Android APK/AAB جاهزة للنشر في المتجر في هذا الفرع.

## بيئة التطوير

يتطلب تشغيل جميع الاختبارات Node.js 22 وJava وFirebase Emulator:

~~~bash
npm install --ignore-scripts --no-audit --no-fund
npm install --prefix functions --ignore-scripts --no-audit --no-fund
npm test
~~~

للمعاينة المعزولة دون اتصال ببيانات العملاء:

~~~bash
npm run build:hosting
~~~

يبني ذلك `dist/` ببيانات Firebase معطّلة؛ **ليس نسخة صالحة للاستخدام الحقيقي**. يفحص CI الواجهة على الكمبيوتر والهاتف ويتحقق من حسابات ومراجعات ومدفوعات وهمية في المحاكيات.

## حزمة Staging

استخدم مشروع `souqna-staging` وإعدادات Web SDK التابعة له فقط؛ لا تحفظها في GitHub ولا تخلطها مع الإنتاج. راجع [دليل تشغيل Staging](docs/STAGING_SETUP_AR.md) و[فحوصات قواعد الاستخدام](docs/HELP_AND_LEGAL_RELEASE_AR.md). يتوفر مسار Windows محمي، لكنه لا ينبغي تنفيذه إلا بعد اعتماد المالك للنصوص وصلاحياته الفعلية.

## إصدار Production

راجع [خطة الإطلاق النهائي وخريطة Go/No-Go](docs/FINAL_LAUNCH_PLAN_AR.md). بعد دمج PR #3 وPR #4 باعتماد صريح واختبارات Staging الحقيقية:

~~~powershell
$env:SOUQNA_PRODUCTION_BUILD_APPROVED = "souqna-sweida:2026-11-19"
npm run build:production
npm run preflight:production
npm run preflight:launch
~~~

`build:production` يبني حزمة محلية فقط، و`preflight:production` يفحص الملفات. بعد أي نشر معتمد منفصل يمكن تشغيل `npm run check:production:hosting` للتحقق من ملفات الويب المنشورة على النطاقين الافتراضيين دون تعديل السحابة. `preflight:launch` يرفض الترخيص إذا لم يتحقق من الفرع `main` وبناء الإنتاج ونجاح فحوص Staging الحية وموافقات المالك. لا ينشر أي أمر منها الموقع أو يفعّل الفوترة أو Cloud Functions.

**لا تشغّل `firebase deploy` على `souqna-sweida` بناءً على نجاح المحاكيات وحده.** يلزم نسخ احتياطي واستعادة مختبرة، اعتماد القواعد والدوال والواجهة معاً، وتأكيد اسم الجهة القانونية وطرق الدعم وسياسة الاسترداد.
